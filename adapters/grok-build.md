# Grok Build adapter

Grok Build can be an external terminal worker now, using an explicitly reviewed command profile whose required flags are validated against the installed CLI's help and whose authentication/model check succeeds. The official xai-org/grok-build-plugin-cc bridge documents noninteractive prompt, plan/read-only and workspace modes, cwd and output options. Different CLI versions expose different machine-output and effort dialects. Never infer support by replacing a model suffix or using an arbitrary executable named grok.

The runtime's request/result contract is independent of Grok being the coordinating host. When Grok Build becomes coordinator, map its actual native subagent, question, plan, permission and lifecycle tools through this contract. Use its native Grok roles and authenticated external Codex/Claude terminal workers. Project role policy, upstream pin and verification obligations remain shared.

The Grok host adapter requires live verification of skill loading, command dialect, final-result schema, identity, read-only enforcement and cancellation before claiming coordinator parity. Missing CLI or authentication is an unavailable lane. No implicit provider fallback is permitted.
