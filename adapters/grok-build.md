# Grok Build adapter

Grok Build is an external response-only worker through [the runtime](../runtime/README.md). The exact dialect is `{"id":"grok-build-1","confinement":"response-only"}` with portable `mode: "read-only"`. The runtime sends a private prompt file with approved context and returns a response artifact. Model tools must be absent in native init. The parent coordinator inspects the artifact, writes files, and runs verification.

The named profile checks installed help, the authenticated available-model catalog, and native discovery before dispatch. It rejects discovered hooks, MCP servers, project instructions, and plugins. Agents must be built-ins. Skills must be built-ins or bundled skills under the canonical Grok home's `bundled/skills` directory. It disables compatibility scanners, memory, subagents, file writing, tool discovery, and web search. The native event parser checks served model and session independently from billing labels. Server-bundled skills and slash commands can remain observed in init metadata. Effort support remains argv evidence unless native execution metadata proves more.

Native bwrap confinement failed on the current cloud host, and Landlock was unavailable. The response-only profile explicitly uses native sandbox `off` and `dontAsk` with every model tool excluded. It provides no verified filesystem or credential isolation and refuses portable `isolated-write`. A separate worktree alone does not qualify a writer. Future file-tool or writer support requires a verified host executor or mediated tool service. Never infer support by replacing a model suffix or using an arbitrary executable named grok.

The runtime's request/result contract is independent of Grok being the coordinating host. When Grok Build becomes coordinator, map its actual native subagent, question, plan, permission and lifecycle tools through this contract. Use its native Grok roles and authenticated external Codex/Claude terminal workers. Project role policy, upstream pin and verification obligations remain shared.

The Grok host adapter requires live verification of skill loading, command dialect, final-result schema, identity, confinement, and cancellation before claiming coordinator parity. The response-only external worker does not establish that parity. Missing CLI or authentication is an unavailable provider. Doctor preflights do not prove authenticated model execution. Quota and concurrency remain unknown. No implicit provider fallback is permitted.
